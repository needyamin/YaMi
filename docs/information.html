Fontaine AI

A small foundation-model project: prepare a code corpus, train a decoder-only Transformer, and chat with the checkpoint in the browser. Commands below assume Git Bash in the project folder.

cd /c/YaMi

What it is

Fontaine is a config-driven decoder-only language model (RoPE, grouped-query attention, SwiGLU, RMSNorm, optional QK-norm and sliding-window attention, and mixture-of-experts). Sizes are YAML files, not separate codebases. The reference corpus is CodeAlpaca-20k, rendered in the Alpaca template (### Instruction: / ### Response:). Chat uses that same template, so you type a normal question and the server wraps it.

PieceRole
ModelThe network. Dense configs use every weight on every token. Coding configs are a mixture of experts: all experts are stored (total parameters), and only the top 1 or 2 run per token (active parameters).
TokenizerByte-level BPE dictionary in datasets/tokenizer. The model and the tokenizer must stay paired.
CheckpointA saved snapshot under experiments/<run>/checkpoints. Pointing at the checkpoints folder serves the newest step.
DockerOne CPU image. web is the API, webui is Open WebUI, train is a one-off training run. Weights stay on the host; they are not baked into the image.

Model sizes

Counts below are what fontaine model inspect prints. Dense rows assume an 8k vocabulary. Coding and Yami rows use the vocabulary written in each file (Yami: 32k). Training memory follows total parameters, because every expert is stored. Inference cost follows active parameters.

The Yami rows add QK-norm (each attention head normalizes its queries and keys, which keeps training stable) and, on Base and Large, sliding-window attention: three of every four layers look only at the last 1,024 tokens, so long prompts cost less. None of the Yami configs is trained yet.

python -m fontaine.cli.main model inspect --model-config configs/model/yami_small.yaml
python -m fontaine.cli.main model recommend

model recommend reads your CPU cores and RAM and names the largest Yami tier that fits. When you train any config, set data.sequence_length to at most that model’s max_sequence_length. A longer data window is rejected.

Folders

datasets/ downloads/ original files, as downloaded raw/ converted text the pipeline is allowed to read prepared/ packed token shards + manifest.json (built by commands) tokenizer/ the dictionary experiments/ training output only: logs and checkpoints configs/ model, data, training, and inference settings .env which checkpoint the chat API serves, and the host ports
downloads → raw → tokenizer + prepared → experiments → chat
Data rules. Do not drop datasets into experiments/. Do not edit datasets/prepared by hand. data prepare overwrites that folder, and tokenizer training reads everything currently in datasets/raw. Accepted inputs are listed under Data below.

Data

Put any mix of these in datasets/raw. Everything is read as a stream; archives are never extracted to disk.

KindFilesOne document is
Plain text.txta paragraph
Prose and markup.md, .rst, .html, .texthe whole file
Source code.py, .js, .ts, .java, .cpp, .go, .rs, .sql, Dockerfile, and morethe whole file
Records.jsonl, .json, .csv, .tsv, .parquetone record
Notebooks.ipynbmarkdown and code cells
Archives.zip, .tar, .tar.gz, .tar.xz (nested too)each file inside, by its own type
Compressed files.gz, .bz2, .xz, .zstthe file inside

A record can hold plain text, a chat (messages with role/content, or ShareGPT conversations), or an instruction pair (instruction, optional input, output; also prompt/response and question/answer). Chat and instruction records are written in the same ### Instruction: / ### Response: layout the chat server uses. Images and other binary files are skipped with a warning. Use the hf_bpe tokenizer for mixed data: it encodes any language or symbol. Details: docs/data/pipeline.md.

CodeAlpaca-20k is the reference corpus: about 20,000 instruction and answer pairs. Download it, then rewrite each record into one text line.

mkdir -p datasets/downloads
curl -L -o datasets/downloads/code_alpaca_20k.json \
  "https://huggingface.co/datasets/sahil2801/CodeAlpaca-20k/resolve/main/code_alpaca_20k.json"

python tools/prepare_codealpaca.py \
  --input datasets/downloads/code_alpaca_20k.json \
  --output datasets/raw/codealpaca_20k.jsonl

A converted line looks like this. Chat prompts use the same shape, ending at ### Response: so the model writes the answer:

{"text": "### Instruction:\nCreate an array of length 5 which contains all even numbers between 1 and 10.\n\n### Response:\narr = [2, 4, 6, 8, 10]"}
python -m fontaine.cli.main tokenizer train \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' \
  --set tokenizer.type=hf_bpe

python -m fontaine.cli.main data prepare \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' \
  --license "Apache-2.0"

Preparation writes datasets/prepared/manifest.json. An earlier CodeAlpaca tiny run on CPU (5,000 steps) reached val loss 2.14 and perplexity 8.5. That is the expected quality of the tiny model: short, style-matched code, not a general assistant. That run is no longer in this folder.

Current state. The only run in experiments/ is 2026-09-24_083835_quickstart: a 3.2M model trained for 200 steps on a toy word list with a 99-token vocabulary. It is what the chat serves today, and it usually returns an empty reply or random words. Chat then shows a short status message explaining that the model stopped before writing. Train a real corpus to get real answers.

Train

Docker is the default path. It already passes the prepared manifest, studies the tiny model for 5,000 steps, and writes the run back to experiments/ on the host.

docker compose run --rm train

The same run without Docker. The manifest line is required. Without it the trainer rebuilds an empty dataset.

python -m fontaine.cli.main train \
  --model-config configs/model/tiny.yaml \
  --training-config configs/training/local.yaml \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set data.manifest_path=datasets/prepared/manifest.json

A coding model uses its own config and a matching sequence length. Example for the laptop tier:

python -m fontaine.cli.main train \
  --model-config configs/model/coding_low.yaml \
  --training-config configs/training/local.yaml \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set data.manifest_path=datasets/prepared/manifest.json \
  --set data.sequence_length=512

loss on the training split should fall. val_loss falling, then flattening, means the run has learned what this size can learn. If validation loss rises again, the model is memorizing; stop or train for fewer steps.

Chat

Copy .env.example to .env and set FONTAINE_CHECKPOINT to the container path of a run’s checkpoints folder. A missing folder makes the API fail at startup. Ports: the API is 8321 on the host (FONTAINE_PORT), and Open WebUI is 3000 (WEBUI_PORT).

cp .env.example .env
docker compose up -d web webui

Open http://localhost:3000. Open WebUI talks to the Fontaine API over the Ollama protocol (/api/chat, /api/tags, /api/show). The model picker shows Yami v1.0, and the context control uses the checkpoint maximum. You do not type the Alpaca wrapper. Sampling defaults for code are temperature 0.2, top-p 0.9, and a light repetition penalty. The API also stops a chat reply before a fake next ### Instruction:. If the model writes nothing or fails, the reply says so instead of staying blank.

On a CPU, models of 20M parameters or more load as int8 weights by default (inference.precision: auto), which cuts weight memory by about 3x. Override with --precision fp32|bf16|int8 and set CPU threads with --threads N on serve and generate. /api/show reports the format as F32, BF16, or Q8_0.

After a new training run, edit .env and recreate the containers. No image rebuild is required unless the Python source changed.

docker compose up -d web webui

The API itself is at http://localhost:8321. A direct check:

curl http://localhost:8321/api/tags
curl -X POST http://localhost:8321/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Write a Python function that adds two numbers."}],"stream":false}'
Local only. There is no login on the API, and Open WebUI auth is off for local development. Do not publish ports 8321 or 3000 on the internet.
