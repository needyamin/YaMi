1What is this project, in plain words?

Imagine a student who learns only by reading. You give the student thousands of examples — questions and answers about computer code. The student reads them over and over, slowly getting better at guessing “what word comes next”. After enough practice, the student can finish your sentences, write small pieces of code, and answer simple questions.

The technical wordWhat it really means
ModelThe student — a computer “brain” that gets smarter with practice.
DatasetThe textbooks — thousands of examples the student reads.
TrainingThe studying — reading the examples again and again, getting a little better each time.
TokenizerThe dictionary — a translator between letters and the numbered pieces the brain understands.
CheckpointA saved snapshot of the brain at one moment — so you never lose progress.
Loss / val_lossThe test score. It must go down. Lower = smarter.
DockerA packed lunchbox: the whole program runs inside a sealed box that works on any computer.
Web playgroundA chat page in your browser where you talk to the trained brain.

2The folder map — where things live

Think of the project as a kitchen. Each folder has exactly one job:

C:\yami\ ├── datasets\ │ ├── downloads\ ← the shopping bag: original files, exactly as downloaded │ ├── raw\ ← the kitchen counter: converted text, ready to cook │ ├── prepared\ ← the packed lunch: final “brain food” (do not edit by hand) │ └── tokenizer\ ← the dictionary ├── experiments\ ← report cards + saved brains — OUTPUT ONLY, never an input ├── configs\ ← recipe cards (settings; change numbers, not code) ├── tools\ ← kitchen gadgets (dataset converters live here) ├── docs\ ← guides (you are reading one) ├── Dockerfile ← the recipe that builds the lunchbox ├── docker-compose.yml ← which boxes to open: web + train └── .env ← the note saying which brain the website serves

Data flows one way only

datasets/downloads  →  datasets/raw  →  datasets/prepared  →  experiments/
   (shopping bag)      (kitchen counter)   (packed brain food)   (trained brains)
   what you            what the machine    tokenizer + shards,   training RESULTS,
   downloaded          is allowed to read  built by commands     never an input
⚠️ TWO RULES: (1) Never put dataset files into experiments\ — that drawer is only for finished brains, and a dataset dropped there is simply ignored. (2) Never put files by hand into datasets\prepared — the machine builds that one. You only ever touch datasets\downloads and datasets\raw.
⚠️ BEFORE ADDING NEW DATA: the packing step (data prepare) overwrites datasets\prepared, and the tokenizer re-learns from everything sitting in datasets\raw — old and new mixed. Want one dataset pure? Move the other files out of datasets\raw first. Old brains are safe either way: each folder in experiments\ is self-contained and keeps working.

3Step 1 — Download a dataset

The best free library is huggingface.co/datasets. Search for words like code, python, or instructions. Good choices:

NameSizeNotes
CodeAlpaca-20ksmall ✅The one this project uses — 20,022 question/answer examples about code.
MBPPtiny (974)A quick practice set — trains in minutes.
CodeSearchNetlargeReal code functions — the next step up.

The real download command used for this project (paste into Git Bash):

mkdir -p datasets/downloads
curl -L -o datasets/downloads/code_alpaca_20k.json \
  "https://huggingface.co/datasets/sahil2801/CodeAlpaca-20k/resolve/main/code_alpaca_20k.json"

What it does: saves the original file (7.7 MB) into the shopping bag. You can also download by clicking on the website and moving the file there by hand — same thing.

The three rules for any dataset:
  • Shape: must be .txt, .jsonl, .json, or .csv. PDFs, Word files, and ZIPs must be converted first — the machine silently ignores anything else.
  • Fields: each example needs a text field (or question+answer fields). Other names need the conversion step below.
  • Size: a few MB is perfect for this computer. Bigger is not better for a tiny student.

4Step 2 — Convert it to the right shape

CodeAlpaca arrives as instruction / input / output records — names Fontaine does not read. The converter gadget rewrites each record into one text document in the classic teaching template:

python tools/prepare_codealpaca.py \
  --input datasets/downloads/code_alpaca_20k.json \
  --output datasets/raw/codealpaca_20k.jsonl

What it does: writes 20,022 lines like this into the kitchen counter folder:

{"text": "### Instruction:\nCreate an array of length 5 which contains all even numbers between 1 and 10.\n\n### Response:\narr = [2, 4, 6, 8, 10]"}

For a different dataset, copy this gadget and adjust it — it is ~40 lines of Python in tools\. If your download is already clean JSONL with a text field, skip this step and drop it straight into datasets\raw.

5Step 3 — Build the dictionary (tokenizer)

python -m fontaine.cli.main tokenizer train \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' \
  --set tokenizer.type=hf_bpe

What it does: reads everything in datasets\raw and teaches the translator 4,096 word-pieces. Result: datasets\tokenizer. (Already done for CodeAlpaca — repeat only for new data.)

6Step 4 — Wash, pack, and seal (validate + prepare)

python -m fontaine.cli.main data validate \
  --data-config configs/data/default.yaml \
  --set 'data.raw_paths=["datasets/raw"]'

python -m fontaine.cli.main data prepare \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' \
  --license "Apache-2.0"

What it does: the first command checks your files (CodeAlpaca: 20,022 documents, 6.7 million characters — OK). The second removes duplicates, translates every document into numbered pieces, and seals them into datasets\prepared with a packing list (manifest.json). Result for CodeAlpaca: ~2 million packed pieces (1.97M study / 96K exam). (Also already done.)

7Step 5 — Train the brain (two ways)

WAY 1 · DOCKER (recommended)

Inside the lunchbox — ≈ 40 minutes

docker compose run --rm train

What it does: opens a training box, studies 5,000 rounds, saves everything through the window into experiments\<date>_fontaine-tiny\, then removes itself. Peek at progress any time from another window:

cat experiments/*/checkpoints/latest.json
WAY 2 · PLAIN WINDOWS

Directly on your computer — same result

python -m fontaine.cli.main train \
  --model-config configs/model/tiny.yaml \
  --training-config configs/training/local.yaml \
  --data-config configs/data/default.yaml \
  --tokenizer-dir datasets/tokenizer \
  --set data.manifest_path=datasets/prepared/manifest.json
⚠️ THE ONE LINE YOU MUST NEVER DELETE (Way 2 only): --set data.manifest_path=datasets/prepared/manifest.json. Without it the trainer rebuilds your packed lunch empty — the Docker way is protected from this, another reason to prefer it.

While it runs you will see loss=... every few seconds — it must go down (the real run went from ~8.3 to ~0.9). Every 100 steps an exam score val_loss appears. This project’s finished run:

MetricStartEndMeaning
val_loss≈ 8.32.14Random guessing → real learning.
val_perplexity40968.5Was choosing between 4,096 options per word — now ~8.

8Step 6 — Chat in the web interface

SETUP · ONCE

Choose which brain the website serves

Open the file .env (in C:\yami) with any text editor and point it at your run’s checkpoints folder:

FONTAINE_CHECKPOINT=/app/experiments/2026-09-22_051929_fontaine-tiny/checkpoints
FONTAINE_PORT=8321

Point at the checkpoints folder (not a step inside it) — the machine always picks the newest saved snapshot automatically.

OPEN

Start the website

docker compose up -d web

Then open http://localhost:8321 in any browser. You should see Fontaine AI — Playground with a green dot (the health light).

CHAT

Ask questions

  • Type a question, press Enter — no special template needed, the page wraps it in ### Instruction / ### Response for you.
  • It remembers the last 3 exchanges — so you can say “now change it to multiply instead” and it understands. The counter in the header shows how much it remembers.
  • ＋ New conversation (top-right button) clears the memory for a fresh topic.
  • Temperature slider: low (0.6–0.8) = safest, most repetitive answers; high (1.0–1.3) = more variety. Max new tokens caps the answer length.
PROGRAMMER'S DOOR

Test without the browser (optional)

curl -X POST http://localhost:8321/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "### Instruction:\nWrite a Python function that adds two numbers.\n\n### Response:\n", "stream": false, "max_new_tokens": 40, "temperature": 0.6}'
✅ REAL ANSWER FROM THIS EXACT SYSTEM: asking “Write a Python function that adds two numbers.” returned def add_two_numbers(num1, num2): return num1 + num2 — correct. Follow-up “Now change it to multiply instead” returned def multiply_two_numbers(a, b): return a * b — it understood the conversation.

val_loss going back up⚠️ Memorizing instead of understanding. Stop, or retrain with fewer steps.

11Common mistakes to avoid

  • Dropping a dataset into experiments\ — wrong drawer; it is output-only and will be ignored.
  • Putting a .zip or .pdf into datasets\raw — quietly ignored. Convert first (Step 2).
  • Editing files inside datasets\prepared — that folder belongs to the machine.
  • Deleting datasets\tokenizer after training — the brain cannot read without its dictionary.
  • Forgetting the manifest line in the no-Docker train command (Step 7, Way 2).
  • Expecting ChatGPT — this tiny student (3–5M parameters, 256-token memory) is for learning the craft. Real quality = bigger model configs (configs/model/small.yaml) on a GPU computer.
  • Exposing the playground to the internet — no login, development-grade server. Your computer only.
