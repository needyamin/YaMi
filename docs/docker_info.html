📦 Fontaine AI — The Docker Guide

From zero setup to asking your own AI questions in a web browser. Written in plain language — every command is copy-and-paste.

1What is Docker? (plain words)

Imagine packing your entire kitchen — stove, tools, ingredients, recipes — into one standard lunchbox that can be opened on any computer in the world and works exactly the same. That lunchbox is a Docker container.

Docker wordPlain meaning
ImageThe packed lunchbox itself — the recipe turned into a ready package.
ContainerA lunchbox currently open and running on your computer.
DockerfileThe written recipe for building the lunchbox.
docker-compose.ymlThe to-do list: which lunchboxes to open, and how they connect to your folders.
Volume (mount)A window between the box and your real folders — so trained models saved inside the box land in experiments\ on your PC.
.env fileA small note that tells the web page which trained brain to serve.
WHY THIS IS NICE: your normal folders stay the source of truth. The container never swallows your data or models — it borrows them through windows (mounts). Train a new model and the website can serve it; no rebuilding needed.

2The four files that make it work

File (in C:\yami)Its job
DockerfileBuilds the box: Python + PyTorch (CPU) + the Fontaine program. Unprivileged user, built-in health check.
docker-compose.ymlDefines the two services: web (the website + answering API) and train (a one-off study run).
.envSays which trained brain the website serves (FONTAINE_CHECKPOINT) and the port (FONTAINE_PORT). Copy from .env.example.
.dockerignoreHousekeeping: keeps your data, models, and caches out of the box.

3One-time setup

SETUP 1

Have Docker Desktop running

You already installed it. Just make sure Docker Desktop is started (whale icon in the system tray). Check it works — open Git Bash and type:

docker --version
docker compose version
SETUP 2

Stand in the project folder

cd /c/yami

All commands below assume you are here.

SETUP 3

Prepare the textbook (already done for CodeAlpaca!)

This part runs on your normal computer, not in Docker. For the current dataset it is finished: data is in datasets\raw, the dictionary in datasets\tokenizer, packed brain-food in datasets\prepared. You only repeat this when bringing a new dataset — the friendly walkthrough lives in info.html, and the commands are:

python -m fontaine.cli.main tokenizer train \
  --data-config configs/data/default.yaml --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' --set tokenizer.type=hf_bpe

python -m fontaine.cli.main data prepare \
  --data-config configs/data/default.yaml --tokenizer-dir datasets/tokenizer \
  --set 'data.raw_paths=["datasets/raw"]' --license "Apache-2.0"

4Start the web interface

STEP 1

Build and open the box

docker compose up -d web

What it does: builds the image the first time (downloads ≈ 1 GB — one coffee), then starts the website in the background.

When it finishes, open http://localhost:8321 in any browser. You should see the Fontaine AI — Playground with a green dot (the health light).

STEP 2

Which brain is it using right now?

Whichever FONTAINE_CHECKPOINT says in the .env file. The value is a path like /app/experiments/<run-folder>/checkpoints. Point it at the checkpoints folder (not a step inside it) and the machine always picks the newest saved snapshot automatically.

5Train inside Docker

STEP 3

The long study session (≈ 40 minutes)

docker compose run --rm train

What it does: opens a second box, reads the packed textbook 5,000 rounds, and prints a loss score that must go down. When it ends, the box removes itself (--rm) — but everything it learned is saved through the window into experiments\<date>_fontaine-tiny\ on your PC.

Peek at progress any time from a second Git Bash window:

cat experiments/*/checkpoints/latest.json
STEP 4

Point the website at the new brain

Open the file .env in any text editor and set the new run folder:

FONTAINE_CHECKPOINT=/app/experiments/2026-09-22_051929_fontaine-tiny/checkpoints

Then refresh the running website so it picks up the change:

docker compose up -d web

(It is smart: it only restarts the website, seconds, no rebuild.)

⚠️ TRAINING DATA MUST EXIST FIRST: train reads datasets\prepared. If that folder is missing or empty, run SETUP 3 above before training.

6Test it in the web browser

STEP 5

Ask questions

On http://localhost:8321, type a question and press Enter. You do not need to type the ### Instruction wrapper — the page wraps your words in that template automatically, because that is the shape the model was trained on.

The two knobs above the chat:

KnobWhat it doesSensible value
TemperatureCreativeness. Low = safe and repetitive, high = wild.0.6 – 0.9
Max new tokensMaximum answer length.120 – 250
STEP 6

Judging the answers honestly

You see…It means…
Word salad, random code wordsThe site is still serving the 1-minute practice brain (50 steps) — do STEP 3.
Short, plausible Python snippets in the right style✅ Training worked. This is the expected quality of a tiny model.
Fluent but wrong answersNormal — the tiny student learned style. Real quality needs the bigger models on a GPU.

You can also test without the browser — the same answer machine has a programming door:

curl -X POST http://localhost:8321/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "### Instruction:\nSay hi.\n\n### Response:\n", "max_new_tokens": 30}'

7Everyday command cheat-sheet

I want to…Type this (in C:\yami)
Open the websitedocker compose up -d web
See if it is healthydocker compose ps — or just look at the dot on the page
Watch its diarydocker compose logs -f web
Train a new modeldocker compose run --rm train
Switch to a new brainedit .env, then docker compose up -d web
Close everythingdocker compose down
After the program code changeddocker compose up -d --build web
⚠️ BE HONEST ABOUT SECURITY: the playground has no login and the answering machine is the simple development one. It is for your computer only — do not forward port 8321 to the internet.
